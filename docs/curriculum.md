# サイバー攻撃対策 学習カリキュラム

## カリキュラム概要

本カリキュラムは、サイバー攻撃を「攻撃者の視点で理解し、守備者の立場で対策する」アクティブ・サイバー・ディフェンスの考え方に基づいて構成されています。

---

## Phase 1: 基礎知識（2〜4週間）

### 1-1. ネットワーク基礎

**目標**: TCP/IP スタックとプロトコルの動作を理解する

| トピック | 内容 | 演習 |
|---------|------|------|
| OSI 参照モデル | 各レイヤーの役割と攻撃対象 | パケットキャプチャ解析 |
| TCP/IP | ハンドシェイク・セッション管理 | Wireshark でのSYN追跡 |
| DNS | 名前解決の仕組みと悪用例 | DNS クエリログ分析 |
| HTTP/HTTPS | リクエスト/レスポンス構造 | ヘッダー検査 |
| ファイアウォール | パケットフィルタリングの仕組み | iptablesルール作成 |

**チェックポイント**:
- [ ] Wireshark でTCPハンドシェイクを確認できる
- [ ] nmap で自分のホストをスキャンできる
- [ ] iptables で基本的なルールを設定できる

### 1-2. Linux / CLI スキル

**目標**: セキュリティツールを効果的に使うための基礎を身につける

```bash
# 必須コマンド
netstat -tulpn          # リスニングポートの確認
ss -tulpn               # ソケット状態確認
ps aux                  # プロセス一覧
lsof -i :80             # ポート80を使うプロセス
find / -perm -4000      # SUID ビットのファイル探索
grep -r "pattern" /log/ # ログ検索
awk '{print $1}' file   # フィールド抽出
```

**チェックポイント**:
- [ ] `grep`, `awk`, `sed` でログを解析できる
- [ ] プロセスとネットワーク接続を関連付けられる
- [ ] cron、systemd サービスを確認できる

### 1-3. 暗号・認証の基礎

| 概念 | 説明 | セキュリティへの関連 |
|------|------|---------------------|
| 対称暗号 (AES) | 同じ鍵で暗号/復号 | データ保護、ランサムウェア |
| 非対称暗号 (RSA) | 公開鍵/秘密鍵 | TLS、SSH認証 |
| ハッシュ (SHA) | 一方向変換 | パスワード保存、整合性確認 |
| JWT | トークンベース認証 | APIセキュリティ |
| MFA | 多要素認証 | アカウント乗っ取り対策 |

## Phase 2: 攻撃手法の理解（4〜8週間）

### 2-1. 偵察（Reconnaissance）

攻撃者が標的を調べる段階。防御者は**何が見えているか**を把握する。

**OSINTによる情報収集**:
```
公開情報 → ドメイン・IP・技術スタック・従業員情報
ツール例  → nmap, shodan, theHarvester, WHOIS
```

**防御のポイント**:
- 不要なポートを閉じる
- バナー情報を隠す（Webサーバーバージョン等）
- DNS情報の最小化
- ハニーポットでスキャンを検知

**演習**: `labs/01-reconnaissance-defense/`

### 2-2. ネットワーク攻撃

| 攻撃手法 | 説明 | 防御策 |
|---------|------|--------|
| ポートスキャン | 開放ポートの探索 | ファイアウォール、IDS |
| ARP スプーフィング | MitM攻撃の準備 | ARP監視、動的ARP検査 |
| DNS ポイズニング | 偽サイトへ誘導 | DNSSEC |
| SYN フラッド | DoS攻撃 | SYN Cookie、レート制限 |
| VLAN ホッピング | ネットワーク分離の回避 | VLANの適切な設定 |

**演習**: `labs/02-network-security/`

### 2-3. Webアプリケーション攻撃（OWASP Top 10）

```
A01: アクセス制御の不備      → 権限チェックのバイパス
A02: 暗号化の失敗            → 平文通信、弱い暗号
A03: インジェクション        → SQLi, コマンドインジェクション
A04: 安全でない設計          → ビジネスロジックの欠陥
A05: セキュリティの設定ミス  → デフォルト設定、不要な機能
A06: 脆弱なコンポーネント    → 古いライブラリ
A07: 認証の失敗              → 弱いパスワード、セッション管理
A08: ソフトウェアの整合性    → サプライチェーン攻撃
A09: ログ・監視の失敗        → 攻撃の見逃し
A10: SSRF                    → 内部サービスへのアクセス
```

**演習**: `labs/03-web-security/`

### 2-4. マルウェアの動作理解

**マルウェアの種類と動作**:
- **ランサムウェア**: ファイル暗号化 → 身代金要求
- **トロイの木馬**: 正規ソフトに偽装してバックドア設置
- **ワーム**: ネットワーク経由で自己増殖
- **ルートキット**: OS レベルで潜伏・隠蔽

**検知と対応**:
1. 異常なプロセスの監視
2. ネットワーク通信の監視（C2サーバーへの通信）
3. ファイルシステムの変更監視
4. メモリフォレンジクス

### 2-5. ソーシャルエンジニアリング

人を騙す攻撃への対策:
- フィッシングメールの見分け方
- 不審なリンク・添付ファイルの確認
- 組織的なセキュリティ意識教育

## Phase 3: 防御の実装（継続学習）

### 3-1. セキュリティ監視（SIEM）

```
ログ収集 → 正規化 → 相関分析 → アラート → 対応
```

**主要な監視対象**:
- 認証ログ（成功・失敗）
- ネットワーク接続ログ
- ファイル変更ログ
- アプリケーションエラー

**演習**: `labs/04-log-analysis/`

### 3-2. インシデントレスポンス

**PICERL フレームワーク**:
```
Preparation     → 準備・訓練
Identification  → 検知・識別
Containment     → 封じ込め
Eradication     → 根絶
Recovery        → 復旧
Lessons Learned → 改善
```

**演習**: `labs/05-incident-response/`

### 3-3. セキュリティアーキテクチャ

- ゼロトラストアーキテクチャ
- 多層防御（Defense in Depth）
- 最小権限の原則
- セグメンテーション
